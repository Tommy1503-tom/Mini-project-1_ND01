# สรุปใจความสำคัญ: ND01-Week01-Introduction
**ทักษะสู่งานวิศวกรรมแห่งอนาคต ในยุค AI**
เอกสารฉบับนี้เน้นย้ำถึงแนวทางการพัฒนาทักษะสำหรับวิศวกรในยุคที่ปัญญาประดิษฐ์ (AI) เข้ามามีบทบาทสำคัญ โดยมีรายละเอียดดังนี้:

## 1. ความเปลี่ยนแปลงในยุค AI และทักษะที่วิศวกรต้องมี
* **บทบาทของ AI:** AI สามารถช่วยสร้างงานและเขียนโค้ดได้ เช่น วงจร, PCB, หรือ Firmware แต่วิศวกรมีหน้าที่ต้อง **ออกแบบ ตรวจสอบ และรับผิดชอบระบบทั้งหมด**
* **ความสมดุลของทักษะ:** วิศวกรต้องมีความเชี่ยวชาญเชิงลึกในด้านใดด้านหนึ่ง พร้อมกับความเข้าใจในภาพรวมของระบบทั้งหมด (System-level understanding) เนื่องจากไม่มีทักษะใดที่รับประกันได้ว่ารูปแบบงานจะไม่เปลี่ยนแปลง
* **หัวใจสำคัญของการทำงาน:**
  * พื้นฐานต้องแน่น (วงจร, สัญญาณ, Control, Timing, Memory, Power)
  * คิดเป็นระบบ กำหนดโจทย์ และอธิบายข้อแลกเปลี่ยน (Trade-off) ได้
  * ทำงานจริง วัดผลได้ ตรวจสอบ Debug และมีหลักฐาน/ผลทดลองรองรับ
  * ใช้ AI อย่างมีวิจารณญาณ (ใช้เพื่อช่วยทำงาน แต่ต้องตรวจสอบความพร้อมก่อนส่งมอบ)

## 2. โครงสร้างหลักสูตรและเทคโนโลยีที่เกี่ยวข้อง (Edge AI & Secured IoT)
เนื้อหาในเอกสารมุ่งเน้นการพัฒนาโปรเจกต์จริงบนฮาร์ดแวร์ เช่น **ESP32-S3** ร่วมกับไมโครโฟนและจอ TFT Touchscreen โดยแบ่งองค์ความรู้เป็น 4 เสาหลักสำคัญ ได้แก่:
1. **Edge AI & Audio Processing:**
   * การประมวลผลเสียงและการทำ Edge AI บนอุปกรณ์ (Inference)
   * การจัดการ Buffer, Preprocessing และการวัดค่าความแม่นยำ (Accuracy) กับความหน่วง (Latency)
2. **FreeRTOS & Firmware Design:**
   * การออกแบบระบบปฏิบัติการแบบ Real-time ด้วย FreeRTOS (การจัดการ Task, Queue, Buffer Ownership, Priority)
   * การป้องกันปัญหา Race Condition ด้วย Mutex และ Semaphore รวมถึงการรับมือความผิดปกติ เช่น เน็ตหลุดแต่ระบบหลักยังต้องทำงานต่อ
3. **Cybersecurity & Communication:**
   * การสื่อสารผ่านโปรโตคอล MQTT over TLS, การจัดการสิทธิ์ (Topic ACL), การตรวจสอบ Server Certificate และการยืนยันตัวตนรายอุปกรณ์
   * การจัดการสถานะการเชื่อมต่อ เช่น Reconnect, Retry และการรับมือข้อมูลซ้ำ
4. **Device Provisioning, OTA & Reliability:**
   * การลงทะเบียนอุปกรณ์และผูกกับเจ้าของตั้งแต่เริ่มใช้งาน
   * การอัปเดตเฟิร์มแวร์ทางอากาศ (OTA) อย่างปลอดภัย เช่น การตรวจลายเซ็น, การทำ Rollback เวอร์ชันเมื่อเกิดความผิดพลาด (เช่น ไฟดับระหว่างอัปเดต) และระบบ Diagnostics

## 3. ความแตกต่างระหว่าง Hobby / Prototype สู่ Product จริง
สิ่งที่ทำให้วิศวกรเป็นที่ต้องการของตลาดและภาคธุรกิจ คือความสามารถในการเปลี่ยนจากโครงงานต้นแบบ (Prototype) ให้กลายเป็นผลิตภัณฑ์ที่ใช้งานได้จริง (Product) โดยคำนึงถึง:
* **การผลิตซ้ำและบำรุงรักษา:** สามารถผลิตซ้ำได้ง่าย ตรวจสอบและซ่อมแซมได้
* **พลังงานและความเสถียร:** มีการวัดการใช้พลังงาน/อายุแบตเตอรี่ และระบบสามารถทำงานต่อเนื่อง รวมถึงกู้คืนตัวเองได้เมื่อเกิดปัญหา (Recovery)
* **ความปลอดภัย (Safety & Security):** ป้องกันความเสียหายจากไฟผิดปกติ และมีความปลอดภัยทางไซเบอร์
* **การดูแลหลังการขาย:** รองรับการวินิจฉัยปัญหาทางไกล การอัปเดต (OTA) และการติดตามรุ่นผลิตภัณฑ์ตลอดอายุการใช้งาน

## 4. เครื่องมือสนับสนุนการเรียนรู้ (Simulator)
* เอกสารยังมีตัวอย่างการใช้งาน **Simulator (Virtual Bench / Board-twin)** สำหรับจำลองการทำงานร่วมกับบอร์ดไมโครคอนโทรลเลอร์ (เช่น การทดสอบ GPIO, LED, 7-Segment, Analog Input, PWM, Microphone และ Speaker) เพื่อให้ผู้เรียนสามารถฝึกเขียนโค้ดและทดสอบระบบผ่านหน้าจอจำลองได้ก่อนใช้งานบอร์ดจริง

# สรุปใจความสำคัญ:# ND01 — Week 02: ES3C28P Hardware & Embedded Fundamentals
### 1. ระบบไฟและการใช้พลังงาน (Power & Battery)
* **แหล่งจ่ายไฟ:** รองรับไฟเข้าผ่าน USB-C (5V) หรือแบตเตอรี่ LiPo (3.7V) ผ่านชิป LDO (ME6217) แปลงเป็นแรงดัน 3.3V เส้นเดียวเลี้ยงทั้งบอร์ด
* **งบกระแสไฟฟ้า:** ตัวควบคุมไฟมีขีดจำกัดกระแส (ประมาณ 500 mA) หากเปิดใช้งานหน้าจอ, ไฟ LED และ Wi-Fi พร้อมกัน อาจทำให้เกิดอาการไฟตก (Rail droop) จนจอหรี่หรือบอร์ดรีเซ็ตเอง
* **การวัดระดับแบตเตอรี่:** ใช้ขา GPIO9 ต่อผ่านวงจรแบ่งแรงดัน (Voltage Divider) โดยต้องนำค่าที่อ่านได้คูณ 2 เพื่อเทียบเป็นแรงดันจริง
* **การจัดการพลังงานขณะนอนหลับ:** การเข้าโหมด Deep Sleep ต้องสั่งปิดไฟหน้าจอ (GPIO45) และชิปเสียงด้วยตนเอง มิฉะนั้นอุปกรณ์รอบข้างจะยังคงดึงกระแสไฟอยู่

### 2. การเชื่อมต่อ USB และพอร์ต Serial
* **สถาปัตยกรรมพอร์ต:** บอร์ดนี้ไม่มีชิปแปลง USB-UART แยก แต่ต่อสาย USB-C เข้ากับ Native USB (GPIO19/20) ของชิป S3 โดยตรง ทำงานเป็น Serial จำลอง (CDC-ACM)
* **กับดักการรีเซ็ตอัตโนมัติ:** ทุกครั้งที่มีการเปิดพอร์ตเชื่อมต่อ (เช่น เปิด Monitor) วงจรจะสั่งรีบูตบอร์ดอัตโนมัติ ทำให้ข้อมูลบรรทัดแรกหายไปหรือกลายเป็นขยะ
* **แนวทางรับมือ:** ให้กำหนดเวลารอ (Settle) ประมาณ 2.5 วินาทีหลังเปิดพอร์ต และใช้สายผ่าน UART0 Header (TX43/RX44) หากต้องการ Serial แท้ที่ไม่รีบูตตัวเอง

### 3. ขา GPIO และการขยายอุปกรณ์ (Expansion Pins)
* **ขาว่างที่ใช้งานได้จริง:** เนื่องจากฮาร์ดแวร์บนบอร์ดถูกเชื่อมต่อไว้เกือบหมดแล้ว ทำให้เหลือขา GPIO อิสระให้ใช้งานเพิ่มได้เพียง 4 ขา คือ **GPIO 2, 3, 14 และ 21**
* **ข้อควรระวังเรื่อง Strapping Pins:** ขา 0, 45 และ 46 มีผลต่อโหมดการบูตเครื่อง ห้ามต่อวงจรภายนอกดึงสัญญาณผิดทิศทางในจังหวะเปิดเครื่อง
* **วิธีแก้ปัญหาขาไม่พอ:** หากต้องการใช้งานอุปกรณ์เพิ่ม สามารถใช้ I2C/SPI Expander (เช่น MCP23017) ช่วยขยายขาได้

### 4. การแสดงผลหน้าจอ (ILI9341V Display)
* **การเชื่อมต่อ:** ใช้จอ IPS ขนาด 240×320 ควบคุมผ่าน SPI 4 เส้น ร่วมกับขาควบคุมสัญญาณ (DC) และขาปรับแสง (BL)
* **เทคนิคเพิ่มความเร็ว:** ใช้เทคนิค Dirty-Rect โดยอัปเดตเฉพาะกรอบสี่เหลี่ยมจุดที่ข้อมูลเปลี่ยนแปลง แทนที่จะส่งข้อมูลภาพใหม่ทั้งจอ
* **การแก้ปัญหาภาพเพี้ยน:** ต้องทำ Byte-swap ข้อมูลสีก่อนส่งเพื่อป้องกันสีแดงสลับกับสีฟ้า และต้องส่งคำสั่งเปิดใช้งาน Inversion (`INVON`) เพื่อไม่ให้สีบนจอแสดงผลกลับด้าน

### 5. ระบบสัมผัสหน้าจอ (FT6336G Touch Layer)
* **ชิปประมวลผลแยก:** ใช้ชิป FT6336G สแกนตำแหน่งการสัมผัสผ่าน I2C แล้วส่งพิกัด $(x, y)$ ให้ MCU อ่านค่า ช่วยลดภาระการประมวลผล
* **วิธีการอ่านข้อมูล:** สามารถเลือกใช้แบบ Polling (วนอ่านข้อมูลเป็นระยะ) สำหรับการใช้งาน UI ทั่วไป หรือใช้ขา Interrupt (INT) เพื่อปลุกระบบเมื่อมีการสัมผัส
* **การแปลงพิกัดหน้าจอ:** หากมีการหมุนหน้าจอเป็นแนวนอน (Landscape) จำเป็นต้องสลับแกนและคำนวณพิกัดใหม่ตามสูตร มิฉะนั้นตำแหน่งทัชจะสลับซ้ายขวา

### 6. ระบบเสียง (Audio Chain - 3 Chips)
* **โครงสร้างการทำงาน:** ประกอบด้วยชิปหลัก 3 ตัวทำงานร่วมกัน ได้แก่ ESP32-S3, ES8311 (Audio Codec) และ FM8002E (Amplifier) พร้อมไมโครโฟน MEMS
* **การแบ่งหน้าที่บัส:** ใช้บัส I2C สำหรับส่งคำสั่งตั้งค่ารีจิสเตอร์ (เช่น ระดับเสียง) และใช้บัส I2S สำหรับสตรีมข้อมูลเสียงจริง
* **จุดที่มักลืมบ่อย:** ต้องสั่งเปิดขา GPIO1 ให้เป็นสถานะ Low เพื่อเปิดใช้งานแอมป์ขยายเสียง (PA Enable) และต้องเขียนโปรแกรมตั้งค่า Codec ทุกครั้งก่อนใช้งาน

### 7. ไฟ LED RGB (WS2812 RMT LED)
* **โปรโตคอลควบคุม:** ใช้สัญญาณพิกัดความกว้างพัลส์เส้นเดียวบนขา GPIO42 โดยไม่มีสัญญาณ Clock แยก
* **การใช้งานฮาร์ดแวร์ RMT:** ห้ามใช้ CPU ควบคุมจังหวะเวลาพัลส์ด้วยซอฟต์แวร์โดยตรง (Bit-bang) เพราะจะทำให้แสงไฟกระพริบหรือสีเพี้ยนเมื่อระบบทำงานหนัก ให้ใช้ฮาร์ดแวร์ RMT ช่วยสร้างสัญญาณแทน
* **รูปแบบข้อมูล:** ข้อมูลสีต้องจัดเรียงในรูปแบบ GRB และควรจำกัดความสว่างของไฟ LED เพื่อไม่ให้ดึงกระแสไฟเกินขีดจำกัดของบอร์ด

### 8. การใช้งานการ์ด MicroSD (SDIO 4-Bit Native)
* **ความเร็วสูง:** ช่องเสียบการ์ดบนบอร์ดเชื่อมต่อด้วยโหมด SDIO 4-bit ใช้สาย 6 เส้น ซึ่งให้ความเร็วในการรับส่งข้อมูลสูงกว่าโหมด SPI ปกติหลายเท่า
* **ระบบไฟล์:** รองรับการใช้งานฟอร์แมต FAT32 สำหรับการ์ดขนาดไม่เกิน 32GB และ exFAT สำหรับการ์ดขนาดใหญ่กว่า
* **ข้อควรระวัง:** ห้ามถอดการ์ดความจำขณะกำลังเขียนไฟล์ และระวังปัญหาไฟตกหากมีการเขียนข้อมูลลงการ์ดพร้อมกับการเปิดใช้งาน Wi-Fi หนัก ๆ

### 9. การติดตั้งเครื่องมือพัฒนา (ESP-IDF Setup)
* **การติดตั้ง:** ติดตั้งผ่าน VS Code Extension "Espressif IDF" แบบ Express เพื่อให้ระบบจัดเตรียมคอมไพเลอร์, เครื่องมือ Flash และสภาพแวดล้อม Python มาให้ครบชุดในที่เดียว
* **กฎการใช้งาน:** การรันคำสั่งคอมไพล์และสร้างโปรเจกต์ต้องทำผ่าน **ESP-IDF Terminal** เท่านั้น พร้อมมีแนวทางตรวจสอบระบบ 4 ระดับ (L1–L4) ตั้งแต่ตรวจสอบเวอร์ชัน ตรวจสอบการสร้างโปรเจกต์ ทดสอบบนบอร์ดจริง จนถึงรัน Firmware สมบูรณ์

### 10. พื้นฐาน Embedded C และ FreeRTOS
* **การใช้ตัวแปร volatile:** ตัวแปรที่ใช้งานร่วมกันระหว่างลูปหลักและฟังก์ชัน Interrupt (ISR) ต้องประกาศด้วยคำสั่ง `volatile` เสมอ และห้ามทำฟังก์ชันบล็อกหรือจองหน่วยความจำ (`malloc`) ภายใน ISR
* **การจัดการหน่วยความจำ:** หลีกเลี่ยงการใช้ `malloc` พร่ำเพรื่อเพื่อป้องกันปัญหาหน่วยความจำแหว่ง (Fragmentation) และควรใช้คีย์เวิร์ด `const` เพื่อเก็บข้อมูลคงที่ไว้ใน Flash แทนการเปลือง RAM
* **การประยุกต์ใช้งาน FreeRTOS:** สามารถแบ่งแยกลักษณะงาน (Task) ไปรันบนหน่วยประมวลผลทั้งสองแกนของ ESP32-S3 (Core 0 และ Core 1) พร้อมใช้เครื่องมือสื่อสารระหว่าง Task เช่น Queue, Semaphore, Mutex และ Task Notification

นี่คือสรุปเนื้อหาคู่มือ **การติดตั้งและตรวจสอบการทำงานของ ESP-IDF (เวอร์ชัน v6.1 สำหรับ ESP32-S3)** เป็นภาษาไทยแบบเข้าใจง่ายและกระชับครับ

คู่มือนี้ใช้สำหรับติดตั้ง **ESP-IDF v6.1** พร้อมเครื่องมือสำหรับ **ESP32-S3** รองรับทั้งระบบปฏิบัติการ **Windows, macOS และ Linux** โดยสามารถเขียนโปรแกรมและ Build ทดสอบได้โดยไม่ต้องใช้บอร์ดฮาร์ดแวร์จริง (แต่ต้องใช้บอร์ดตอนจะ Flash ลงเครื่องจริง)

### 1. สิ่งที่ต้องเตรียมเบื้องต้น
* **อินเทอร์เน็ต** (สำหรับการดาวน์โหลด Framework และ Toolchain ขนาดประมาณ 1 GB ขึ้นไป)
* **พื้นที่ว่างในฮาร์ดดิสก์**
* **Git** และ **Python (เวอร์ชัน 3.10 ขึ้นไป)**
### 2. วิธีการติดตั้งตามระบบปฏิบัติการ
#### 🪟 สำหรับผู้ใช้ Windows (แนะนำให้ใช้ Track A: ผ่าน PowerShell)
1. **ติดตั้ง Git for Windows** และเลือกให้ใช้งานผ่าน Command Line ได้
2. **เปิด Windows PowerShell** (ห้ามใช้ Git Bash เด็ดขาด เพราะระบบจะพังเพราะติดค่า `MSYSTEM`)
3. **ตรวจสอบ Python และ Git:** รันคำสั่ง `python --version` และ `git --version`
4. **ดาวน์โหลด ESP-IDF v6.1:**
* สร้างโฟลเดอร์ เช่น `D:\dev\esp\v6.1\esp-idf`
* ทำการ Clone โค้ดผ่าน Git: `git clone --branch v6.1 --recursive [https://github.com/espressif/esp-idf.git](https://github.com/espressif/esp-idf.git)`
5. **ติดตั้ง Tools สำหรับ ESP32-S3:**
* เข้าไปที่โฟลเดอร์ ESP-IDF แล้วรัน: `.\install.ps1 esp32s3`
6. **เปิดใช้งาน (Activate) และตรวจสอบ:**
* รันคำสั่งเปิดใช้งาน: `. .\export.ps1`
* ตรวจสอบความถูกต้อง: `idf.py --version` (ต้องแสดงผลเป็น **v6.1**)

#### 🍏🐧 สำหรับผู้ใช้ macOS และ Linux (ใช้ Terminal / Bash)
1. **ติดตั้ง Prerequisite Packages** ของระบบปฏิบัติการนั้น ๆ และตรวจสอบ `git --version` / `python3 --version`
2. **ดาวน์โหลด ESP-IDF v6.1:**
* สร้างโฟลเดอร์ `mkdir -p ~/esp && cd ~/esp`
* Clone โค้ด: `git clone --branch v6.1 --recursive [https://github.com/espressif/esp-idf.git](https://github.com/espressif/esp-idf.git)`
3. **ติดตั้ง Tools สำหรับ ESP32-S3:**
* รันคำสั่ง: `./install.sh esp32s3`
4. **เปิดใช้งาน (Activate) และตรวจสอบ:**
* รันคำสั่งเปิดใช้งาน: `. ./export.sh`
* ตรวจสอบความถูกต้อง: `idf.py --version` (ต้องแสดงผลเป็น **v6.1**)

### 3. ข้อควรระวังที่สำคัญ (Troubleshooting)
* ⚠️ **ห้ามใช้ Git Bash บน Windows เด็ดขาด** ให้ใช้ **Windows PowerShell** เท่านั้น เนื่องจาก Espressif Toolchain ไม่รองรับสภาพแวดล้อมแบบ MSYS/MinGW
* **เส้นทาง (Paths):** หลีกเลี่ยงการเว้นวรรค (Spaces) ในชื่อโฟลเดอร์ที่เก็บโปรเจกต์และ Framework
* หากคำสั่ง `idf.py` ไม่รู้จัก ให้ทำการ Activate ทุกครั้งที่เปิด Terminal ใหม่ผ่านไฟล์ `export.ps1` (Windows) หรือ `export.sh` (Mac/Linux)

### 4. เช็กลิสต์ความสำเร็จ (Completion Checklist)
* [ ] ติดตั้ง Git และ Python เรียบร้อย
* [ ] คำสั่ง `idf.py --version` แสดงเวอร์ชัน **v6.1**
* [ ] ตัวแปร `IDF_PATH` ชี้ไปยังโฟลเดอร์ Framework ถูกต้อง
* [ ] สามารถ Build โครงการ (เช่น Hello World) ได้สำเร็จผ่าน `idf.py build`
* [ ] (เมื่อมีบอร์ด) สามารถ Flash และดูข้อความผ่าน Serial Monitor ได้
นี่คือสรุปเนื้อหาคู่มือ **การตั้งค่า ESP-IDF Extension บน VS Code** (ทำหลังจากติดตั้ง ESP-IDF เรียบร้อยแล้ว) เป็นภาษาไทยแบบเข้าใจง่ายครับ

### 📌 ภาพรวมสำคัญ
หน้าต่าง Terminal และส่วนขยาย (Extension) ใน VS Code ทำงานแยกสภาพแวดล้อมกัน ดังนั้นแม้คุณจะรัน `idf.py build` ใน Terminal ได้สำเร็จ **ปุ่ม Build ใน VS Code ก็จะยังใช้งานไม่ได้** จนกว่าจะตั้งค่าให้ Extension รู้จักตำแหน่งของเครื่องมือต่าง ๆ เสียก่อน

### 1. เปิดโฟลเดอร์โปรเจกต์ให้ถูกที่
* เปิดโปรแกรม VS Code และติดตั้งส่วนขยายชื่อ **ESP-IDF by Espressif**
* ไปที่ **File → Open Folder** แล้วเลือกโฟลเดอร์รากของตัวโปรเจกต์เฟิร์มแวร์โดยตรง (โฟลเดอร์ที่มีไฟล์ `CMakeLists.txt` และโฟลเดอร์ `main/` อยู่ข้างใน เช่น `.../esp32-s3`)
* ⚠️ **ข้อควรระวัง:** ห้ามเปิดโฟลเดอร์ใหญ่สุดของ Repository และต้องใช้ VS Code ให้ตรงกับระบบที่ติดตั้ง (เช่น Windows VS Code คู่กับ Windows ESP-IDF หรือ VS Code WSL คู่กับ Linux ESP-IDF)

### 2. ตั้งค่าสภาพแวดล้อมให้ Extension (ทำเพียงครั้งเดียว)
เลือกทำตามวิธีที่คุณใช้ติดตั้ง ESP-IDF ในตอนแรก:
#### 🅰️ กรณีติดตั้งผ่านตัวจัดการ EIM (Espressif Installation Manager)
1. กด `Ctrl+Shift+P` ใน VS Code
2. พิมพ์และเลือกคำสั่ง **ESP-IDF: Select Current ESP-IDF Version** แล้วเลือกเวอร์ชัน **v6.1**
3. รันคำสั่ง **ESP-IDF: Doctor Command** เพื่อตรวจสอบว่า Path ของ Framework, Python, CMake และ Ninja ถูกต้องครบถ้วน

#### 🅱️ กรณีติดตั้งผ่านสคริปต์ (Course Scripts)
ต้องสร้างไฟล์ตั้งค่า `.vscode/settings.json` ในโปรเจกต์เพื่อให้ Extension รู้จักตำแหน่งเครื่องมือ (ค่าเหล่านี้เป็นของใครของมัน ห้ามก๊อปปี้ของเพื่อนมาใช้):
1. เปิด **Windows PowerShell** (ห้ามใช้ Git Bash) ที่โฟลเดอร์โปรเจกต์ และรันคำสั่ง Activate: `..\scripts\start-esp-idf.cmd` (หรือ `. ..\scripts\start-esp-idf.ps1`)
2. ตรวจสอบว่าเครื่องมือพร้อมใช้งานด้วยคำสั่ง `idf.py --version`, `cmake --version`, `ninja --version`
3. รันชุดคำสั่ง PowerShell จากคู่มือเพื่อดึงค่าตัวแปร (Export Environment) และบันทึกอัตโนมัติลงในไฟล์ `.vscode\settings.json` *(สำหรับ macOS/Linux ให้รันผ่าน Bash ตามคู่มือ)*
4. กลับมาที่ VS Code กด `Ctrl+Shift+P` เลือก **Developer: Reload Window** จากนั้นรัน **ESP-IDF: Doctor Command** เพื่อตรวจเช็กความเรียบร้อย

### 3. ทดสอบ Build โปรเจกต์ผ่าน VS Code
1. กด `Ctrl+Shift+P` เลือก **ESP-IDF: Set Espressif Device Target** แล้วเลือกชิปเป็น **`esp32s3`**
2. กดปุ่มรูปเปลวไฟหรือรันคำสั่ง **ESP-IDF: Build your project**
3. รอจนหน้าต่าง Output แสดงข้อความ **`Project build complete`** (จะได้ไฟล์ผลลัพธ์ชื่อ `build/hello_world.bin`)

### 4. การใช้งานในวันถัดไป & การแก้ปัญหาเบื้องต้น
* **การใช้งานประจำวัน:** เมื่อเปิดโฟลเดอร์โปรเจกต์เดิมขึ้นมา สามารถกดปุ่ม Build ใน VS Code ได้ทันทีโดยไม่ต้องตั้งค่าใหม่ (แต่ถ้าจะพิมพ์คำสั่ง `idf.py` เองใน Terminal ใหม่ ยังต้องรันสคริปต์ Launcher เพื่อ Activate เหมือนเดิม)
* **แก้ปัญหา `cmake was not found`:** มักเกิดจาก Extension ยังหา Path ไม่เจอ ให้รัน Doctor Command เช็กดู หรือสร้างไฟล์ตั้งค่าใหม่แล้วสั่ง Reload Window
* **แก้ปัญหาขึ้นแจ้งเตือน `Missing sdkconfig`:** ตรวจสอบว่าคุณเปิดโฟลเดอร์โปรเจกต์ถูกชั้นหรือไม่ (ต้องเป็นชั้นที่มี `CMakeLists.txt`) และลองกด Build รอบแรกเพื่อให้ระบบสร้างไฟล์ `sdkconfig` ขึ้นมาครับ
